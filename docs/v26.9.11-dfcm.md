# avmnif-rs v26.9.11 — DfCM AtomVM Control Plane

## Objective

Port the remaining reusable AtomVM control-plane semantics from `unrdf` into `avmnif-rs` while **increasing composition and decreasing hidden authority**.

The release identifier is `26.9.11`; it is a Chatman ecosystem control-plane release, not a replacement for the crate's Cargo semver.

## DfCM decomposition

The source package combines several concerns in runtime objects. v26.9.11 decomposes them into orthogonal manufacturing stages:

```text
ADMIT TOPOLOGY
    ↓
SELECT ROUTE
    ↓
CONSTRUCT INTENT
    ↓
SEAL INTENT
    ↓
ADMIT RUNTIME + CIRCUIT POLICY
    ↓
PLAN EXECUTION
    ↓
────────────── authority boundary ──────────────
EXTERNAL ADAPTER ACTUATES ATOMVM
    ↓
OBSERVE TERMINATION + MARKER + DIGESTS
    ↓
CLASSIFY STANDING
    ↓
CONSTRUCT RECEIPT
    ↓
SEAL RECEIPT
```

The governing invariant is:

```text
topology != route != intent != seal != admission != plan
         != actuation != observation != classification != receipt
```

No earlier state manufactures authority for a later state.

## Reuse before invention

v26.9.11 composes the v26.9.11 predecessor port rather than creating parallel machinery:

- `runtime_lifecycle` remains the single portable runtime lifecycle.
- `circuit_breaker` remains the single call-admission circuit policy.
- `supervisor` remains the restart-selection policy.
- `hot_code` remains the candidate/commit/rollback state machine.
- `sla` remains the caller-clock observation accumulator.
- `message_validation` remains structural message validation.

New modules fill only missing semantic dimensions:

| Module | Owns | Explicitly does not own |
|---|---|---|
| `evidence` | opaque digest binding and caller-driven verification | hashing algorithm, keys, canonical serialization |
| `swarm` | swarm admission, topology, deterministic BFS route selection | sockets, cookies, DNS, network connection |
| `intent` | route-bound intent body and external seal | payload serialization, random IDs, wall clock, execution |
| `execution` | operation admission, runtime-ref selection, observation classification, receipt body | filesystem, process spawn, timers, stdout/stderr collection, hashing |
| `control_plane` | composition of runtime-ready and circuit admission | process execution |

## Source mapping

### `unrdf/packages/atomvm/src/swarm-cluster.mjs`

Portable:

- stable identifier grammar
- duplicate-swarm refusal
- `atomvm://` endpoint admission
- authority-reference requirement
- undirected topology
- deterministic shortest-path routing
- route-bound intent construction
- intent drift checking
- receipt identity/replay concepts

Environment/domain-specific and therefore excluded from the Rust core:

- `randomUUID`
- SHA-256 implementation
- wall-clock ISO timestamps
- N-Quads/RDF serialization
- JavaScript object freezing
- direct broker invocation

### `unrdf/packages/atomvm/src/process-broker.mjs`

Portable:

- only `atomvm.execute` is admitted
- selected route must terminate at selected target
- target must have a runtime configuration
- zero exit + required marker is the ALIVE observation rule
- nonzero exit, timeout, spawn failure, or missing marker is BLOCKED
- stdout/stderr are represented by evidence digests

Environment-specific and therefore excluded from the Rust core:

- `fs.stat`
- `child_process.spawn`
- `SIGKILL`
- environment variable inheritance
- Node timers
- SHA-256 implementation
- filesystem path truth

## Evidence model

`Digest32` is deliberately opaque. The crate does not silently select a hashing algorithm or canonical serialization.

```text
body + externally manufactured digest → Sealed<body>
Sealed<body> + external digest function → verified | drift
```

This permits BLAKE3, SHA-256, hardware-backed signatures, or future PQC envelopes without making the portable AtomVM policy depend on one scheme.

A seal is identity evidence only:

```text
sealed intent != admitted intent
sealed intent != executed intent
sealed receipt != independently verified execution
```

## Execution plan vs actuation

`ExecutionPlanner` emits opaque references such as `application_ref` and `library_refs`. It does **not** claim those references are files or that AtomVM is installed.

The external adapter must independently establish those facts and perform the process operation. Its result is returned as an `ExecutionObservation` and classified by the portable layer.

This preserves BRCE-style zero-unreceipted-actuation separation:

```text
SELECT/CONSTRUCT (portable)
DO               (environment adapter)
VERIFY/RECEIPT   (portable classification + external evidence)
```

## DfCM option preservation

The design intentionally preserves these future choices:

1. Native AtomVM process adapter vs host subprocess adapter.
2. SHA-256 vs BLAKE3 vs signed/PQC receipt envelopes.
3. Filesystem AVM bundles vs embedded flash/resource references.
4. Single-node vs federated swarm topology.
5. Direct execution vs brokered execution vs simulator execution.
6. Existing Rust runtime support vs future BEAM-facing NIF projection.
7. RDF projection in `unrdf` vs non-RDF consumers in `avmnif-rs`.

None requires changing the pure topology/intent/execution contracts.

## Acceptance boundary

### Locally decidable by Rust tests

- stable IDs refuse invalid input
- admission rejects duplicate swarms and missing authority references
- route selection is deterministic and shortest-path
- intent route endpoints are preserved
- intent drift is refused before planning
- `atomvm.execute` is the only process operation admitted by the planner
- target/runtime mismatches refuse
- process observations map deterministically to ALIVE/BLOCKED
- receipt sealing remains separate from observation classification
- runtime + circuit admission never advances runtime state to Executing

### Requires external evidence

The following remain `UNKNOWN` until an integration environment supplies receipts:

- AtomVM binary availability
- AVM application/library availability
- real process spawn
- timeout enforcement
- marker emitted by real AtomVM code
- stdout/stderr digest calculation
- real NIF invocation
- hot-code replacement of executable BEAM/AVM code

Therefore unit-test success can establish the **portable policy boundary** as ALIVE without claiming the **real AtomVM execution boundary** is ALIVE.

real_execution   = atomvm_available ∧ avm_available ∧ spawn ∧ marker ∧ receipt
